# Project overview

## Working title

AI Tool Governance & Risk Assessment Framework

## Problem statement

Organisations increasingly use AI tools for communication, content creation, information work, and workflow execution. Adoption decisions are often made tool by tool, without a consistent way to consider the intended use, data involved, reliability, affected stakeholders, human oversight, and consequences of failure.

This project develops a structured, proportionate assessment approach that can help an organisation ask better questions before adopting an AI tool and identify safeguards for a defined use case.

## Aim

To develop and demonstrate a repeatable framework for assessing selected AI tools and their organisational risks through documented research, practical testing, and qualitative analysis.

## Objectives

1. Define a consistent set of assessment dimensions for different AI tool categories.
2. Select one accessible, representative tool from each of four categories.
3. Review provider documentation and relevant independent governance sources.
4. Design and conduct small, repeatable tests using synthetic or non-sensitive inputs.
5. Record evidence, limitations, risks, and uncertainty transparently.
6. Compare the tools without assuming that one tool or category is inherently safe or unsafe.
7. Recommend proportionate organisational controls and adoption conditions.

## Scope

### Included

- Conversational AI chatbots
- AI agents and agentic workflow tools
- AI image-generation tools
- AI video-generation tools
- General organisational use cases
- Provider-level and use-case-level considerations
- Qualitative assessment of likelihood, impact, controls, and residual risk
- Human oversight, accountability, and monitoring recommendations

### Excluded

- Building a software application, website, or database
- Model training or fine-tuning
- Large-scale statistical benchmarking
- Formal penetration testing or security testing
- Testing that bypasses provider safeguards or violates terms
- Processing confidential, personal, or otherwise sensitive data
- Legal advice, certification, or claims of regulatory compliance
- Claims that a small number of tests establishes overall model safety

## Assessment unit: tool and use case

A tool cannot be assessed meaningfully in isolation from its intended use. The project will therefore distinguish:

- **Tool/provider-level assessment:** capabilities, published policies, data-handling information, transparency, controls, and known limitations.
- **Use-case-level assessment:** the task, users, affected people, information involved, consequences of error, human review, and organisational context.

The same tool may be appropriate for a low-impact drafting task but unsuitable for a high-impact decision without substantial additional controls.

## Initial testing target

Approximately eight test cases per category (around 32 in total) is an initial planning target, not a mandatory quota. The final number may change based on tool access, test quality, and the evidence needed to answer the assessment questions.

## Deliverables

- A common assessment framework
- A documented testing methodology
- Four tool assessments, one per category
- Test records and evidence notes
- Risk registers
- A comparison across the selected tools
- Practical organisational recommendations
- A short limitations and future-work section

## Project principles

- Evidence before conclusions
- Clear separation of facts, observations, and interpretation
- Proportionate testing
- Human accountability
- Data minimisation
- No unsupported safety or compliance claims
- Reproducibility where practical
- Explicit recording of unknowns and limitations
